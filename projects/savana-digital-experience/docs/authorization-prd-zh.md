# Savana｜老客授权登录与发券 PRD

版本：V0.3 · 2026-10-26 · 基于项目负责人描述回溯整理。

文档性质：已确认的功能事实、补充建议与待确认规则分开表述。本稿不是历史原始 PRD，也不代表建议规则均已上线。数值、资格、库存和优惠计算等参数须由实际业务确认。

## 1. 已确认能力与目标

Savana 支持 Urbanic 老用户授权后一键登录，自动关联或创建 Savana Account，并在登录成功后发放 Welcome Coupon。目标是明确账户进入方式，让用户在知情确认后完成登录，并清楚理解是否获得权益及如何使用。

本模块从授权说明开始，到登录与优惠券最终结果及继续购物入口结束。具体资格、券值、门槛与发放次数尚未提供。

## 2. 用户故事

作为 Urbanic 老客，我希望知道将授权哪些信息、如何登录 Savana、能获得什么权益；取消时可以退出；已登录后领券失败时不必重新登录。

## 3. 授权与账户路径

| 状态 | 建议交互 | 待确认 |
| 展示授权 | 说明账户关系、范围、用途，提供确认与取消 | 实际权限、协议与文案 |
| 用户确认 | 经正式授权验证身份与账户关系 | 凭证与过期处理 |
| 用户取消 | 不建立新授权态，不发券 | 是否允许游客浏览 |
| Savana 账户关联 / 创建 | 授权成功后自动关联已有账户或创建新账户 | 账户匹配、手机号重复、冲突与解绑的细则 |
| 授权成功 | 建立 / 恢复登录态，再校验权益资格 | 不同来源、已登录用户处理 |

建议不静默合并冲突账户，不用客户端传入的用户 ID 或来源参数作为授权依据。

## 4. 资格与发券路径

资格判定与发放由对应服务返回。可能的检查项包括老客身份、活动有效性、已领记录和券库存，但是否采用这些条件需业务确认。

符合资格 → 创建唯一业务请求 → 发券 → 返回最终权益结果。建议同一业务请求重复发送返回一致结果，避免网络重试重复发券。

无资格 / 已领 → 告知实际结果，提供查看已有权益或继续购物。处理中 / 未知 → 查询业务记录；确认失败后按规则重试或补发，不因未知结果反复创建新发券请求。

## 5. 反馈矩阵

| 登录结果 | 权益结果 | 建议页面状态 |
| 未登录 | 不执行发券 | 继续授权或退出 |
| 登录成功 | 发放成功 | 展示权益条件、查看 / 使用入口 |
| 登录成功 | 无资格 / 已领 | 说明原因，正常继续购物 |
| 登录成功 | 明确失败 | 保留登录态，单独处理权益恢复 |
| 登录成功 | 未知 / 处理中 | 提示查询中并提供后续查询方式 |
| 授权失效 | 不继续发券 | 重新授权后复核请求结果 |

## 6. 权益展示与下游规则

成功后的目标激活路径为 Coupon Feedback → Shop Now → Browse → Add to Bag → Coupon Applied → Checkout。实际用券仍以适用规则为准，不能保证每个购物车自动适用。

建议成功态呈现面额 / 折扣、有效期、使用门槛和适用范围，以正式配置为准。给出查看优惠券与继续选购入口；原来源有效且可恢复时返回目标，否则默认页。

券是否可用于 Flash Sale 或 1 元购、是否互斥、门槛如何计算、运费是否参与，均需统一规则。不能默认发券后立即可用于所有商品。

## 7. 事件与指标

事件：授权展示、确认、取消、成功 / 失败，资格结果，发券请求、最终结果、权益查看与使用。

授权成功率以进入授权流程的用户为分母；发券成功率以符合资格且应获券用户为分母。登录与发券分别统计，避免混淆失败原因；定义统计窗口、重复用户及补发口径。

## 8. 验收与待确认

验收授权成功、取消、失效、账户冲突、已领、无资格、发券失败、处理中、重复请求与恢复；确认取消不发券，登录不因券失败丢失，券结果可查询。

待确认账户模型、授权范围、资格、券参数、次数、库存、活动周期、补发责任和优惠关系。当前规则建议不能代替正式授权和权益协议。


## 更新说明与评价边界

体验目标是 Migration + Activation，以 Low Friction 和 Immediate Reward 衔接继续购物。新增边界包括手机号重复、券失效与券不可用。指标覆盖 Authorization Rate、Login Completion、Coupon Claim、Coupon Usage、First Purchase Conversion；暂无各项实测结果。
