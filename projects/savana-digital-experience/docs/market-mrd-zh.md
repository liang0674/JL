# Savana｜市场需求 MRD（精简版）

V0.1 · 2026-10-27 · 基于项目早期定位资料及负责人经历回溯整理。

本稿归纳当时的商业问题与产品方向，不作为原始历史文档或新增市场研究报告。人群占比为早期规划口径；后续公开增长数据不用于反推立项依据。

## 1. 商业机会｜承接品牌升级中的差异化需求

Urbanic 向更高的品牌与价格定位发展后，不同预算、年龄和价格偏好的用户需要差异化承接。Savana 以更易负担的时尚定位覆盖年轻女性需求，在保留品质预期的同时，强调自信、品质与性价比。

立项判断：独立品牌需要让用户看懂新的价值主张，并形成独立的数字产品体验；机会来自已有客群与目标需求之间的衔接，不依赖未经提供的市场规模或增长率预测。

## 2. 目标人群与需求

早期规划的 Savana 目标人群为：16–24 岁约 40%、25–32 岁约 45%、32–40 岁约 15%。这是目标结构，非实际获客或上线后统计；原分组在 32 岁存在交叠，边界待核对。

需求归纳：在可承受预算内发现适合自己的风格；通过商品图、材质与规格信息判断品质；在移动端顺畅浏览、选择和购买；理解价格、优惠和参与条件。

以上需求是基于项目定位的归纳，不声称来自新增访谈、问卷或可用性研究。

## 3. 冷启动挑战

- 品牌认知：Urbanic 用户为什么需要另一个 App？需要先提供商品、价格、风格与品牌价值。
- 访问与迁移：从 Urbanic 到 Savana 的下载、唤起和账户进入存在行为成本。
- 首次激活：登录完成后，还需要继续浏览与购买的理由。
- 持续访问：大量 SKU 中需要易理解的商品发现与价格入口。
- 购物信任：活动价格、资格、库存与应付金额在不同页面必须可解释。

## 4. 已有资源与交付约束

团队可利用 Urbanic 第一方用户基础、成熟技术架构、商品与交易能力、已验证的购物 UX 模型，以及供应链基础。用户基础的规模与客群重合度未提供量化验证。

采用 Platform Reuse + Experience Customization：复用底层与核心 UX，优化浏览体验，重建 Savana 品牌与 UI，并定制增长产品。App 从设计到正式上线不到两个月，是整体团队交付周期；不据此编造阶段排期或分项效率。

## 5. 产品策略与优先级

| 策略 | 对应问题 | 产品能力 |
| 商品价值先行 | 为何迁移到新品牌 | Urbanic 内 Savana 商品专区与跨端导流 |
| 低摩擦进入与即时权益 | 重复注册及首次激活动机 | 授权一键登录、账户关联 / 创建、Welcome Coupon |
| 长期价格与商品发现 | 浏览决策和再次访问理由 | 首页 Flash Sale、商品池、时间 / 库存 / 价格信息 |
| 全链路低价活动 | 放大引流与交易、保护价格理解 | Mega Promotion 与跨页面活动规则 |

上述为业务角色与依赖顺序，不代表历史开发排期。四项能力不构成每位用户都必须经过的串行路径。具体页面、状态、参数与接口由对应 PRD 展开。

优先保证可用购物基础、品牌独立表达、访问与账户承接；促销功能按业务配置进入交易链路。重建成熟高风险交易能力不属于差异化的首要投入。

## 6. 成功标准与验证方式

| 阶段 | 评价方向 | 需定义的口径 |
| Acquisition | 模块点击、市场到达、安装、首次启动 | 去重、跨端关联与观察窗口 |
| Migration | 授权与登录完成 | 进入流程的有效用户、失败原因 |
| Activation | 获券、继续浏览、首购 | 资格用户、激活事件与首次购买窗口 |
| Conversion | 加购、结算、提交及支付结果 | 漏斗分母、有效订单、取消退款 |
| Retention | 再次访问与复购 | 队列、观察周期、真实复购定义 |

以上是评价框架，没有补造指标目标或功能级提升结果。早期业绩与后续公开品牌表现分别呈现在成果和长期验证栏目，并明确团队归属与数据来源。

决策需持续核对真实市场与币种、账户与隐私授权边界、优惠资格及叠加、库存与支付规则，以及各增长功能的实际表现。MRD 提供需求与方向，PRD 承接可执行规则。
