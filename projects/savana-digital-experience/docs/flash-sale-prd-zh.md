# Savana｜首页 Flash Sale PRD

版本：V0.3 · 2026-10-26 · 基于项目负责人描述回溯整理。

文档性质：已确认的功能事实、补充建议与待确认规则分开表述。本稿不是历史原始 PRD，也不代表建议规则均已上线。数值、资格、库存和优惠计算等参数须由实际业务确认。

## 1. 已确认能力与目标

Flash Sale 是 Savana 首页核心板块，通过持续呈现特价商品吸引用户浏览。目标是把商品价格吸引力连到可理解的选择和购买过程。

更新资料确认：Flash Sale 为首页长期促销产品，使用有限商品池、限时优惠 / Countdown、Limited Inventory / Stock Status，以及 Original Price → Sale Price 的价格差表达。目标包括流量、价格认知、转化与再次访问。开售提醒、轮次、预约、库存锁定及保价机制未获确认；具体时长、库存分配与阈值仍需补充。

## 2. 用户任务与范围

Home → Flash Sale Entry → Flash Sale Feed → Product Detail → Size / Variant → Add to Bag → Cart → Checkout。结算后按商城订单 / 支付协议承接结果。

覆盖首页模块及其商品目的地、商品详情、规格、购物车和结算衔接。订单与支付能力为需与现有商城对齐的关联范围，不假设采用新的独立交易系统。

## 3. 活动与商品状态建议

| 状态 | 展示建议 | 行为建议 |
| 配置中 / 未生效 | 不对普通用户展示无效活动价 | 正式生效逻辑待确认 |
| Upcoming | 说明即将开始与有效时间 | 倒计时依据统一时间，不承诺未确认的预约 |
| Active / Ending Soon | 展示有效价格、库存与倒计时 | 临近结束提示阈值待确认 |
| 部分规格不可售 | 区分商品和 SKU 可售性 | 禁用不可售规格，保留有效选择 |
| Countdown End / Campaign Ended / Product Disabled | 停止过期价格、说明失效或商品禁用 | 重新确认有效价格或继续浏览 |
| Refresh / 空商品 / 加载失败 | 按最新有效状态刷新，不展示假价格 | 保留有效选择，重试或其他商品入口 |

## 4. 入口、列表与商品信息

建议模块清楚标识 Flash Sale，商品卡展示商品、实际可用价格与必要条件。若有对比价，其定义、来源和有效性由业务确认，不随意使用“原价”标签。

已确认存在 Flash Sale Feed 作为入口后的商品浏览场景。具体“查看全部”控件、商品顺序、更新频率及 Feed 交互细节待补充。首页与目标页使用同一活动信息，避免点击后活动价无解释地消失。

## 5. 规格与加购

建议选规格后明确对应 SKU 的价格与可售状态；若不同规格优惠不同，在用户确认前说明。加购时校验 SKU、数量、价格与活动有效性。

未选必选规格 → 定位待选项；售罄 → 说明并允许换选；价格变化 → 展示差异并请求确认。不可用规则不采用客户端本地判断作为最终依据。

## 6. 购物车、结算与订单衔接

购物车建议标识参与活动的商品及有效优惠，数量变化后同步校验。进入结算和提交订单时重新确认活动、可售数量、资格与金额；校验节点和请求协议由开发对齐。

活动在浏览 / 加购后结束时，需要说明受影响商品及新价格，允许修改或移除。是否为购物车保价、保留活动价、锁库存及锁定时长均待确认，不能以“加入购物车”暗示保价。

支付失败 / 未知时遵循商城订单查询协议，先查订单结果，避免鼓励重复付款。订单取消、退款是否恢复活动资格 / 库存另行确认。

## 7. 优惠、时间与库存参数

待确认活动周期、时区、市场 / 币种、SKU 范围、限购、库存来源与锁定、对比价、优惠券与 1 元购的价格优先级、运费与门槛。

若正式规则有起止时间，由统一时间源判断有效状态，不只依赖用户设备时间。倒计时作为已确认机制，仍需明确时间源、刷新策略、结束态与弱网恢复；不能只依赖设备本地时间。

## 8. 事件与指标

建议记录模块曝光、商品点击、活动目的地到达、选规格、有效加购、进入结算、订单提交、支付最终结果，以及售罄 / 结束 / 变价中断。

区分模块点击率、有效加购率、提交率、支付成功率；明确分母、观察窗口、活动用户与订单归因。同一商品可能来自多入口，不能把全部特价商品成交归因给首页模块。

## 9. 验收与待确认

检查首页与详情价格一致、SKU 状态正确、数量变化校验、跨活动结束、库存变化、优惠不可用、请求重复与支付结果未知。检查双语长文本和不同市场价格表达。

必须确认活动机制与时间、真实页面路径、库存与保价、优惠计算及订单协议后，才能形成实施规格。


## 更新说明与评价边界

长期产品定位为 Traffic × Conversion × Retention。更新商品池与明确时间、库存、价格信息旨在降低选择负担并形成再次访问理由。评价包括 Module CTR、PLP → PDP、Add to Cart、Conversion、Repeat Visit；这些是评价维度，不能据此宣称已提高留存。
