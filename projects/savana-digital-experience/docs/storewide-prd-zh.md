# Savana｜Mega Promotion 大型低价增长活动 PRD

版本：V0.3 · 2026-10-26 · 基于项目负责人描述回溯整理。

文档性质：已确认的功能事实、补充建议与待确认规则分开表述。本稿不是历史原始 PRD，也不代表建议规则均已上线。数值、资格、库存和优惠计算等参数须由实际业务确认。

## 1. 已确认能力与目标

项目开展大型全场低价增长 Campaign，内部以“1 元购”为核心概念，App 全场景支持对应活动链路。目标覆盖 Acquisition、Activation、Brand Awareness 与 Transaction Scale。目标是让活动权益和商品购买在所有相关触点保持一致，用户能够知道如何参与、为何可用或不可用、最终支付什么。

“1 元购”在更新资料中明确为内部活动概念，并非已确认的各市场对外结算口径。具体结算币种、资格、适用商品、限购、运费和优惠叠加尚未确认；不得由活动名称推断这些参数。

## 2. 用户路径与活动边界

活动触点 → 理解规则 → 校验参与资格 → 选择商品与规格 → 加购 → 购物车复核 → 结算校验 → 订单 / 支付结果。

用户可从首页、列表、商品详情等真实活动触点进入，并非必须经过独立活动页。更新资料确认主链路覆盖 Home、PLP、PDP、Cart、Checkout、Payment、Order Success，并包含活动入口、发现与推荐、价格 / 资格决策、结果反馈等层次。具体页面样式与局部交互仍需设计稿补证。

## 3. 页面覆盖与信息一致性

共同机制包括 Promotion Tag、Price Hierarchy、Qualification、Inventory、Limit、Countdown、Conflict 与 Failure。原则是让用户在结算前看到的价格和优惠，在结算时仍可被解释；不依赖突然变价或无法理解的规则。

| 场景 | 建议承担的活动信息 | 校验 / 状态重点 |
| 首页 / 活动入口 | 名称、核心利益、必要条件、规则入口 | 活动生效与入口有效性 |
| 搜索 / 分类 / 商品列表 | 活动商品与价格 / 资格提示 | 标签与真实适用范围一致 |
| 商品详情 | 商品资格、活动价、参与条件 | 当前用户与 SKU 是否适用 |
| 规格选择 | 可售规格、数量、对应价格 | 不同 SKU、库存与限购 |
| 购物车 | 商品活动状态、数量、优惠说明 | 资格变化与促销冲突 |
| 结算 | 商品金额、优惠、运费、最终应付 | 提交前统一校验与重新确认 |
| 订单结果 / 详情 | 实际支付金额、订单与下一步 | 支付状态、资格是否已消耗 |
| 优惠券 / 营销关联场景 | 活动关系与可用性解释 | 是否可叠加及不可用原因 |

## 4. 资格与次数规则建议

先展示必要参与条件；资格检查失败要反馈具体可解释的原因，不把所有失败都写成“系统繁忙”。登录要求、是否新客、是否需先领资格、单人 / 单单 / 单 SKU 限制等均待确认。

若活动存在次数消耗，需定义何时占用、何时确认、取消 / 超时 / 退款后是否释放。客户端反馈应以服务端状态为准，重复提交不能重复消耗同一资格。

## 5. 商品选择与购物车

建议展示有效活动价格，允许在活动条件内选择规格与数量。库存、资格和价格在加购、购物车刷新及结算时按照正式协议校验。

不符合条件的商品或数量，说明受影响部分并提供改选 / 调整入口。是否允许活动与普通商品混合结算、同单多个活动商品，以及是否每件都为活动价，需业务明确；不静默替用户改变商品或优惠。

## 6. 结算与价格规则

结算需明确商品小计、活动优惠、其他优惠、运费 / 必要费用和最终应付。活动名中的“1 元”不应掩盖未确认的运费或费用。

授权券、Flash Sale 与本活动是否叠加、互斥及优先级需要统一决策。若不可用，解释原因并允许用户按实际能力选择或修改。

提交前资格、活动或库存变化时，展示变化及新金额，用户确认后继续；不得在金额已变化时无提示提交。

## 7. 状态与异常矩阵

| 状态 | 建议反馈 | 恢复 |
| 未满足登录 / 资格 | 明确所需条件 | 按真实能力登录 / 查看规则 / 继续普通购物 |
| 活动未生效 / 已结束 | 展示当前有效状态 | 退出活动或重新确认正常购买 |
| 可选规格售罄 | 禁用对应项并说明 | 换规格 / 换商品 |
| 达到限购 / 资格已使用 | 显示实际限制 | 调整数量或查询关联订单 |
| 购物车与结算价格不同 | 告知受影响商品与金额 | 重新确认或修改 |
| 提交重复 / 超时 | 阻止重复操作，查询订单结果 | 根据最终结果继续 |
| 支付失败 / 结果未知 | 区分明确失败与待查询 | 遵循商城订单与支付协议 |
| 取消 / 退款 | 告知实际结果及资格变化 | 资格与库存恢复依正式规则 |

## 8. 事件与指标

事件建议：活动曝光 / 进入、规则查看、资格结果、商品选择、有效加购、结算到达、提交、支付最终结果、退出及异常恢复。

指标建议：符合资格用户参与率、有效加购率、结算到提交转化、最终支付成功率、资格 / 价格中断率。定义入口归因、合格分母、时间窗口、取消退款口径；不把活动订单数等同净新增用户数或长期留存。

## 9. 验收与待确认

按上述覆盖表逐场景检查同一用户与同一商品的活动信息；覆盖资格变化、不同 SKU、数量修改、活动结束、售罄、混合购物车、优惠冲突、费用变化与重复提交。

待确认市场 / 币种、活动周期、参与资格、适用范围、每单 / 每人 / SKU 数量限制、运费、优惠优先级、库存与资格占用释放、订单支付退款协议及真实页面范围。


## 更新说明与评价边界

增长评价范围新增 Campaign Exposure、Campaign CTR、New User Acquisition、Activation、Add to Cart、Order、Conversion、CAC 和 Repeat Purchase。CAC 需要成本与有效新增口径，复购需要明确观察周期；项目暂未提供这些功能级结果。
