# Savana｜0→1 Growth Product System 总览 PRD

版本：V0.4 · 2026-10-26 · 基于项目负责人描述回溯整理。

文档性质：已确认的功能事实、补充建议与待确认规则分开表述。本稿不是历史原始 PRD，也不代表建议规则均已上线。数值、资格、库存和优惠计算等参数须由实际业务确认。

## 1. 背景与目标

Savana 在 Urbanic 品牌升级与客群分层的背景下，以更易负担的时尚定位覆盖年轻女性需求。增长体验以 Acquisition → Migration → Activation → Conversion → Retention 为生命周期框架；大型活动承担 Scale 角色。我的角色为 Product Design Lead — 0→1 & Growth，参与并主导功能定义、增长体验、交互、UI 与可复用规则。

已确认四项能力：Urbanic 核心板块展示 Savana 商品并支持应用市场 / App 跳转；Urbanic 老客授权登录 Savana 并获券；首页核心 Flash Sale 特价商品板块；App 全场景支持全场 1 元购大促链路。

目标：让用户能理解将前往哪个品牌、完成账户进入、看懂权益与活动条件，并在购物各环节获得一致的价格和状态反馈。

## 产品架构与交付策略（新增确认）

App 从设计到正式上线不到两个月，采用 Platform Reuse + Experience Customization。此周期涵盖整体团队交付，不是技术从零开发的周期或个人独立完成时间。

| 层级 | 策略 | 范围 |
| Technology Foundation | 高度复用 Urbanic 平台 | 账户、商品、购物车、结算、支付、订单、库存、搜索、推荐、后台与 App 框架 |
| Core UX | 继承有效模型并优化 | 浏览、搜索、筛选、PDP、购物车、Checkout、订单 |
| UI & Brand | 全面重新建立 | 品牌视觉、字体、色彩、版式、组件外观、图像与反馈 |
| Custom Product | 针对增长定制 | 跨品牌导流、账户迁移与 Welcome Coupon、Flash Sale、Mega Promotion |

平台策略由团队共同采用。我的职责侧重保留 / 优化 / 重建的体验优先级判断、独立品牌与 UI 体系、增长功能定义与交互，以及设计系统支持的多页面交付。设计、产品与开发并行协作；逐阶段时间、节省成本和分项效率比例未提供。

## 2. 功能边界与文档关系

| 子 PRD | 起点 → 终点 | 核心职责 |
| 跨品牌导流 | Urbanic 商品入口 → Savana 有效落地 | 品牌、目的地与跨端上下文 |
| 授权登录与发券 | 授权说明 → 登录与权益结果 | 账户关系、资格、权益状态 |
| Flash Sale | 首页特价入口 → 活动订单结果 | 特价商品发现与购买衔接 |
| 全场 1 元购 | 活动触点 → 活动订单结果 | 全 App 活动一致性与资格校验 |

四项并非必须串行。用户可以直接打开 Savana，也可以取消授权；Flash Sale 与 1 元购是两类促销场景，并不意味着先经过前者再进入后者。

## 3. 公共信息与建议规则

新增已确认机制：已安装用户 Deep Link 唤起，未安装用户前往 App Store / Google Play；授权后一键登录并自动关联 / 创建账户，登录后 Welcome Coupon；Flash Sale 使用有限商品池、时间 / 倒计时、库存及价格差；大型低价活动覆盖完整购物主链路。具体实现与参数继续单独确认。

| 公共对象 | 建议维护信息 | 责任边界 |
| 访问来源 | 入口、商品、目标路由、市场、语言 | 来源标记不替代身份凭证 |
| 账户 | 授权事务、登录结果、账户关联状态 | 经授权服务验证，不由客户端猜测关联 |
| 优惠券 | 权益标识、资格、有效期、适用范围、领取结果 | 具体券规则待确认 |
| 活动商品 | 活动、商品 / SKU、可售状态、价格有效性 | 展示与结算使用一致的有效规则 |
| 订单 | 商品、数量、优惠明细、应付金额、支付状态 | 最终校验与金额由相应服务返回 |

建议保留可恢复的商品上下文；授权取消与发券失败分别处理；优惠规则变化必须说明影响，不能静默改变应付金额。跨安装上下文恢复、库存锁定和优惠叠加均不得在方案未确认时承诺。

## 4. 优惠关系决策表

| 场景 | 需确认 | 建议体验 |
| 授权券 × Flash Sale | 是否可用、门槛、基准价格 | 展示可用 / 不可用及原因 |
| 授权券 × 1 元购 | 是否互斥、活动价是否计入门槛 | 以有效规则反馈，不默认叠加 |
| Flash Sale × 1 元购 | 同一商品是否同时参与、价格优先级 | 页面统一展示实际有效价格 |
| 活动价 × 运费 | 运费承担、包邮条件、费用范围 | 区分商品优惠与运费 / 其他费用 |
| 多市场与语言 | 币种、时区、活动地区、文案 | 按实际市场配置，不能由“1 元”推断结算币种 |

## 5. 交付与跨团队协同

设计负责入口、信息层级、主路径、状态与恢复说明；产品确认资格、活动、优惠和边界；客户端与服务团队确认路由、授权、权益、库存、价格及订单协议；运营确认配置、活动表达和规则；数据团队确认去重与归因口径。

具体职责与团队结构为协作建议，需按当时实际参与方核对。历史 UI、交互和上线记录是下一轮补证材料。

## 6. 验收与指标

验收：入口目的地清楚；跨端失败可恢复；授权取消不会发券；发券重试有结果查询；促销价格跨页面一致；规则变更可解释；活动结束 / 售罄有可继续的操作；中英文信息完整。

指标建议按各链路分别统计：导流到达、授权成功、符合资格用户获券、促销点击 / 加购 / 下单 / 支付成功、异常恢复。统一定义用户 / 会话 / 事件粒度、统计窗口、有效流量与跨端关联范围。

已提供的日销与 DAU 属于整体业务成果，不作为单项功能的因果证据。

## 7. 待确认清单

市场与币种、平台与链接协议、账户关联、券规则、活动周期、商品范围、限购、库存与锁定、价格优先级、运费、支付与退款、归因窗口。按“业务确认 → 原型及状态确认 → 接口与事件确认 → 验收”推进。


## 更新说明与评价边界

增长设计原则：通过明确价值、降低操作成本、价格可及与购物连贯性，连接 Business Goal、User Motivation、Product Mechanism 和 Experience Design。Retention 是持续商品、促销和内容更新的目标角色，不应与已验证的留存提升混同。
