# Savana｜Urbanic 老客导流与授权领券 PRD

版本：V0.1 · 2026-10-26 · 回溯整理与规则建议稿。

资料依据：项目负责人提供的功能描述。本文不是原始历史 PRD，也不代表所有规则已经实现；已确认功能、建议规则、待确认参数分别标注。流程图表达目标交互，不是已完成的原型或技术协议。

## 1. 业务背景

Urbanic 品牌升级与价格带上移后，Savana 以更易负担的时尚定位覆盖不同预算偏好的用户。Urbanic 内的 Savana 商品板块提供已有流量触点；授权登录和优惠券用于衔接老用户进入新品牌后的体验。

## 2. 已确认能力与范围

已确认：Urbanic 内有核心板块展示 Savana 商品，支持跳转应用市场、唤起 Savana App；Savana 支持 Urbanic 老客授权直接登录并发放优惠券。

本期建议范围：商品板块进入、跨 App / 应用市场承接、授权登录、用户与领券资格校验、发券反馈、优惠券查看与继续选购、异常恢复。

关联范围：Flash Sale 与全场 1 元购作为后续购物场景。本期不定义其完整商品、库存、支付及履约规则，也不默认与授权优惠券叠加。

## 3. 产品目标与用户任务

业务目标：让 Urbanic 用户理解 Savana 的商品与价值主张，并顺利进入 Savana；在用户明确授权的前提下完成登录，通过优惠权益承接后续购物。

用户任务：看到感兴趣的商品 → 明确将进入 Savana → 打开 / 安装 App → 理解并完成授权 → 确认登录和权益结果 → 继续选购。

衡量方向：跨端跳转到达率、授权成功率、符合资格用户的发券成功率、领券后继续浏览与购买表现。当前没有该链路实测数据，不设虚构的提升目标。

## 5. 页面与交互要求

### 5.1 Urbanic 商品板块

建议展示 Savana 品牌、商品图、商品名称、可准确获得的价格与行动入口。跳转前明确将前往 Savana，避免用户误以为仍在 Urbanic 内下单。

点击后进入目标路由处理；短时间内限制重复触发。商品价格、货币与活动说明依实际市场配置，展示数据不作为最终结算价格承诺。

待确认：板块位置、展示数量、更新方式、点击整卡还是独立按钮、用户能否选择应用市场，以及实际覆盖系统与市场。

### 5.2 跨端跳转与应用市场承接

建议根据可用的链接能力与入口配置尝试进入 Savana；唤起未获确认时提供重试、应用市场与返回入口。不将固定超时简单等同于「未安装」，不承诺所有环境都能准确识别安装状态。

前往应用市场后，用户完成安装再打开 Savana。首次安装后的来源 / 商品上下文是否可恢复，需要验证链接方案与平台能力。不能恢复时进入明确的默认页面，仍可继续发现商品。

待确认：链接机制、路由参数、来源标记、跨安装上下文能力、无商品 / 下架商品的目标页与第三方环境限制。

### 5.3 Savana 授权登录

建议先说明将使用 Urbanic 账户登录 Savana、授权信息范围和用途，提供确认及取消操作。由现有登录和授权方案验证身份，不仅依赖客户端传入的用户标识。

授权成功 → 建立 / 恢复 Savana 登录态 → 进入资格校验。取消授权 → 保持未登录并提供再次授权或退出；不能取消后仍自动登录或发券。

待确认：Urbanic 未登录时的路径、已有 Savana 账户的匹配规则、账号冲突与绑定流程、授权失效、可用的其他登录方式、取消后是否允许游客浏览。

### 5.4 资格校验与发券

建议由服务端判定资格并记录发放结果，使用业务唯一标识避免重复请求造成重复发券。老客身份、领券记录、活动有效性与券库存等仅在业务采用对应规则时参与判定。

满足规则 → 发放成功 → 展示可理解的权益结果与使用入口。无资格 → 说明原因并允许继续正常购物。结果处理中 / 未知 → 查询发放记录后再决定是否重试，不能把未知状态直接当成失败。

待确认：是否所有授权老客均获券，还是仅部分人群；是否首次登录限领、单人次数、券额度、有效期、门槛、可用品类、库存与补发规则。上述参数不可直接按行业惯例定案。

### 5.5 领券结果与继续购物

建议区分「登录成功」「已获券」「未获券 / 不符合条件」「权益查询中」。登录成功但发券失败时保留登录态，避免用户重新授权。

成功态展示券面额 / 折扣、有效期、使用条件与查看入口，以实际券配置为准。继续选购优先返回仍有效且可恢复的商品 / 来源场景；无法恢复时进入明确默认页。

优惠券到 Flash Sale 或 1 元购是否可用，由各活动适用规则判定，前端展示与结算结果保持一致。

## 6. 状态与异常矩阵

| 状态 / 触发 | 建议页面反馈 | 恢复与结束条件 |
| 目标 App 未获打开确认 | 提供可理解的跳转帮助 | 重试、应用市场或返回；不能仅凭超时断言未安装 |
| 安装后丢失商品上下文 | 正常进入 Savana 默认体验 | 保持可浏览；来源归因与恢复能力待验证 |
| 商品已下架 / 路由无效 | 告知原商品暂不可查看 | 提供其他商品或首页入口 |
| 授权取消 | 不建立新授权登录态 | 重新授权或退出；浏览能力待确认 |
| 授权凭证无效 / 过期 | 告知授权未完成 | 重新授权，不发券 |
| 账户匹配冲突 | 明确需要处理账户关系 | 按确认后的绑定方案处理，不静默合并 |
| 无领券资格 / 已领 | 明确权益结果与可查询入口 | 可继续购物；实际原因由规则返回 |
| 登录成功、发券失败 | 保留登录状态，单独反馈权益问题 | 查询结果并按补发 / 重试规则恢复 |
| 发券结果未知 / 重复请求 | 显示查询中，避免重复触发 | 按唯一业务记录返回最终结果 |
| 网络中断 | 保留安全可恢复的上下文 | 重试前校验授权与权益结果 |

## 7. 信息与系统协同

建议明确 Urbanic 客户端、Savana 客户端、账户授权服务、优惠券服务及来源记录各自职责。客户端负责路由与状态呈现，账户与权益判定以相应服务结果为准。

协同字段建议：来源渠道、入口 / 活动标识、目标路由、商品标识、语言 / 市场、授权事务标识、发券业务标识与结果码。字段名与接口协议由相关团队确认，不在本稿假定已有实现。

来源参数不能替代登录凭证；链接、埋点和普通日志中不放置可重放凭证或原始个人身份信息。必要身份交换走正式授权协议。

## 8. 事件与指标口径建议

| 事件 | 目的 | 关键维度建议 |
| 商品板块曝光 / 点击 | 评估导流入口 | 入口、商品、市场、活动 |
| 跳转发起 / App 到达 | 评估承接 | 路由、目标环境、可关联来源 |
| 授权展示 / 确认 / 取消 / 成功 / 失败 | 找到授权中断点 | 授权事务、结果码 |
| 领券资格结果 / 发券请求 / 最终结果 | 评估权益承接 | 活动、资格结果、发券业务标识 |
| 继续选购 / 用券 / 下单 | 观察后续行为 | 可适用权益、关联订单与时间窗口 |

指标建议：模块点击率 = 有效点击用户 / 有效曝光用户；可关联跳转到达率 = 可关联到达用户 / 相同来源跳转用户；授权成功率 = 授权成功用户 / 进入授权流程用户；发券成功率 = 最终发放成功用户 / 符合资格且应发券用户。

跨端关联、去重粒度、统计窗口和无法关联的流量需要先定义。后续购买归因还需确认观察窗口与实验方式，不将总销量或 DAU 直接归因于该链路。

## 9. 验收场景建议

- 可用 App 路径与应用市场路径都有明确落点和返回方式。
- 唤起未确认、安装后无上下文、商品失效均有可继续的路径。
- 授权成功、取消、过期及账号冲突分别呈现正确结果。
- 未授权、无资格用户不被错误发券；已授权但领券失败不被强制重新登录。
- 重复点击、重试和网络超时不会按建议幂等规则造成重复发券。
- 发券成功、已领、无资格、失败及未知结果可以区分。
- 权益条件、活动商品价格与结算采用同一有效规则，不默认优惠叠加。
- 中英文和不同目标市场的信息完整、金额与时间表达一致。
