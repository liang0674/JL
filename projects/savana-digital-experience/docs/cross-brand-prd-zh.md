# Savana｜Urbanic 跨品牌导流 PRD

版本：V0.3 · 2026-10-26 · 基于项目负责人描述回溯整理。

文档性质：已确认的功能事实、补充建议与待确认规则分开表述。本稿不是历史原始 PRD，也不代表建议规则均已上线。数值、资格、库存和优惠计算等参数须由实际业务确认。

## 1. 已确认能力与目标

Urbanic 内核心板块展示 Savana 商品，支持跳转应用市场、唤起 Savana App。目标是将商品兴趣承接到 Savana，明确新品牌目的地，减少跳转中断。

本模块结束于 Savana 有效落地；授权、发券和购买由后续模块处理。更新资料确认了已安装 / 未安装两条产品路径：已安装通过 Deep Link 唤起，未安装进入 App Store / Google Play，并覆盖 iOS / Android。安装状态识别、平台链接协议与安装后恢复原商品的具体实现仍需核对。

## 2. 用户故事与入口

作为 Urbanic 用户，我希望先通过商品、价格、风格与品牌视觉理解 Savana 的价值，再决定是否进入新 App；点击后知道会去哪里，并在失败时可以恢复。Product Value First：先建立价值感知，再推动迁移。

建议商品卡展示品牌、图片、名称、可信价格及清晰行动入口；商品详情可承载更多信息，是否存在中间页待确认。避免将跨品牌商品表现为可直接在 Urbanic 内完成交易。

## 3. 主路径与路由规则

| 步骤 | 建议行为 | 待确认 |
| 浏览商品板块 | 显示品牌与目标，准确展示商品 | 模块位置、商品数量、推荐规则 |
| 点击商品 / 行动按钮 | 防止重复触发，记录最少必要来源 | 整卡 / 按钮点击、用户选择方式 |
| 进入目标路由 | 使用已确认链接方案唤起或前往市场 | 支持系统、环境、路由协议 |
| App 打开确认 | 对有效商品或场景落地 | 可检测信号、目标路由能力 |
| 市场安装后打开 | 有能力则恢复上下文，否则默认页 | 跨安装承接与归因能力 |

唤起超时或无确认不直接判定未安装。恢复入口建议包括重试、应用市场、返回 Urbanic。自动跳转策略及等待时长待平台方案验证。

## 4. 异常与恢复

| 情况 | 建议反馈与恢复 |
| 链接无效 / 路由异常 | 明确未能打开，提供重试与替代入口 |
| 商品已下架 | 说明原商品不可查看，转向其他商品或首页 |
| 应用市场不可用 | 保留返回和重试方式；替代下载渠道待确认 |
| 用户安装后丢失来源 | 正常进入默认体验，不阻断浏览 |
| 用户中途取消或返回 | 不假定已成功到达，不发券 |
| 网络中断 / 重复点击 | 避免多次跳转，恢复后按实际结果继续 |

## 5. 上下文与协同建议

传递最少必要的入口、活动、商品、语言与市场信息；来源链接不包含可重放凭证，不用来源标记自动建立登录态。链接格式、有效期、校验及目标数据获取由相关团队确认。

原始目标不可恢复时要有明确默认页；是否保留上次浏览上下文、默认页内容与登录触发时机待确认。

## 6. 事件与衡量

建议事件：模块曝光、商品点击、路由发起、市场跳转、可关联 App 到达、失败恢复。

点击率 = 有效点击用户 / 曝光用户；可关联到达率 = 可关联到达用户 / 同来源发起跳转用户。统计窗口、去重和无法关联流量单独说明，不将应用市场跳转等同安装或激活。

## 7. 验收与待确认

验证可唤起 / 无到达确认、市场路径、安装后有 / 无上下文、商品失效、返回取消、重复点击和双语表达。确认模块交互、目标平台、链接与安装承接方案、归因字段、失败页与返回行为后，方可定稿。


## 更新说明与评价边界

新增确认的评价指标：Exposure、CTR、Store Visit Rate、Install Conversion、First Open、Migration Conversion。安装、首次启动和迁移完成分别定义，不能相互替代。具体归因能力与数据结果尚未提供。
