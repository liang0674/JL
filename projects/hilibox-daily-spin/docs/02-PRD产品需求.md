# 美妆电商每日幸运转盘｜PRD 产品需求文档

版本：V1.0 · 2026-10-23 · 独立产品案例

案例声明：本项目用于美妆电商产品设计与前端演示。品牌背景、经营规模、业务问题、预算及目标均为模拟，不对应任何真实商家，不构成已验证的商业效果。页面、商品、价格、库存和中奖结果均用于演示。

## 1. 产品定位及交付状态

为移动端美妆电商提供每日轻量参与、样品发现和优惠购物路径。交付物为纯静态HTML/CSS/JavaScript原型及本案例文档；无真实账号、订单、数据库或后端依赖，可用于独立静态站点展示。

原型默认模拟登录，演示库存及奖品保存在当前浏览器，存储受限时使用内存。它不是可直接运营的发奖系统。

## 2. 功能范围

| 能力 | 案例需求 | 当前演示 |
| --- | --- | --- |
| 活动参与 | 每账号每日2次基础机会 | 本机模拟额度，非真实账号账本 |
| 更多机会 | 有效邀请带来1次额外机会 | 本机模拟，不能证明跨设备去重 |
| 奖项 | 3—8格、普通券与最多1个实物格 | 默认8格，可配置场景 |
| 实物池 | 一个实物格下可配置多个真实商品 | 唇膏、精华、面霜3个SVG案例 |
| 权益记录 | 可查询、领取及恢复状态 | 浏览器内模拟 |
| 免费订单 | 中奖后指定商品0元且包邮 | 不创建真实订单，正式能力待开发 |
| 国际化 | 英语/阿语及RTL，中文辅助演示 | 已有原型展示；价格单位IQD仅为显示样例 |
| 开关/期限 | 活动启停、入口展示、权益到期 | 本地状态场景，无运营后台 |

## 3. 案例规则与待确认策略

每日基础2次；登录账号在网页与客户端应共享额度。分享页允许先浏览，正式产品抽奖须登录；原型以模拟身份跳过真实登录。

每个有效新设备打开邀请链接可为邀请者增加1次；每日分享不限次数，同设备在同活动周期只贡献一次，禁止自邀。此为案例策略示例，生产去重范围、风险控制及赠次到期时间应重新评审。

普通券有效期示例为领取后72小时，正式系统以服务端绝对到期时间为准。面额、门槛、叠加和适用范围由运营配置。演示中的券金额不能直接当作推荐经营方案。

实物中奖资格、概率和商品分配权重需要运营确认；原型中的低概率及强制中奖开关仅用于展示不同状态，不构成商业建议。若采用已购用户资格，应说明其对新客体验和成本的影响，不把该策略写成唯一正确规则。

## 4. 核心用户流程

站点入口→活动页→浏览奖品与规则→正式环境登录/注册→读取额度与记录→点击抽奖→确认结果→动效结束主动弹窗→领取或关闭→继续参与/进入购物。

普通券：领取成功→显示券信息与期限→前往适用商品列表。实物：结果展示具体中奖商品→领取指定SKU免费权益→正式系统进入既有地址及结算→提交成功创建订单。静态演示不包含真实商品列表、登录、支付或地址结算页面。

分享网页：打开链接→品牌中性活动头部→浏览→正式环境登录参与→领取时引导客户端或项目配置的兑换渠道。当前下载引导中的外部链接属于演示遗留跳转，不是本案例商业主体或依赖，正式案例部署应替换为自有链接或中性提示。

## 5. 页面与展示要求

手机内容视窗375×812，设计图@3x为1125×2436。演示器外框为10px纯色圆角壳，不属于实际活动内容区。页面纵向滚动；原生滚动条隐藏、不占位，滚动时以3px悬浮条显示，650ms后淡出、250ms动画。

商品轮播每3500ms切换有库存商品，保留圆点、不显示数字计数。商品标题12px、600字重、最多3行省略；图片完整展示不裁剪。原价划线，0 IQD附中奖后说明，不误导为无条件免费购买。无原价时隐藏划线金额。

三件美妆商品的名称、原价、SKU及图均为演示值。实物格只显示奖项文字，商品图放独立展示模块和实际结果弹窗。轮播当前商品不决定中奖商品。

## 6. 库存与权益状态

部分售罄：已无库存商品退出可用轮播。全部售罄：保留实物格和一件预览，显示已抽完/Sold out并隐藏中奖后0价；其他券继续参与。补货后恢复。生产中已有中奖用户的预占权益不能被其他用户看到售罄而撤销。

正式服务需要原子扣次、确定奖项、分配实物和预占库存；查询及重试返回同一结果。记录保存实际商品快照，之后换图/下架不改变中奖内容。

权益状态建议为中奖待领取、已领取待下单、已下单、已失效。领取成功不等于订单创建，订单创建不等于实际支付或签收。

## 7. 请求与异常

| 场景 | 期望行为 |
| --- | --- |
| 配置加载 | 禁止点击并明确提示 |
| 请求或动画中 | 禁止连点，不产生重复请求 |
| 次数耗尽 | 提示剩余0，可引导分享；不展示未开放积分 |
| 超时未知 | 保留请求ID，锁定写入，查询原结果后恢复 |
| 明确失败 | 保留权益，允许安全重试，不伪造成功 |
| 登录过期/换账号 | 正式环境重新鉴权并重读记录，账号间隔离 |
| 活动关闭 | 禁止新增抽奖和分享赠次，保留合法历史权益 |
| 缺图/缺价 | 中性占位，不展示其他商品冒充实际奖品 |

默认12秒超时仅为原型参数；服务端requestId幂等、权益唯一消费和设备去重需另外实现。

## 8. 正式系统接口能力规划

getConfig提供活动与奖池，getState查询账号次数及记录，draw生成权威结果，claim签发权益，createShare签发邀请，openShare登记有效访问。它们是能力名称，不代表已部署HTTP地址。

商品配置应有稳定商品池ID、实际SKU、多语言名称、真实图片、原价、可用库存；实物结果必返实际商品快照。结算服务验证中奖账号、SKU、券、库存、有效期、商品应付0及运费0。原型静态参数不授予真实优惠。

## 9. 数据与验收

分析链路：入口实际曝光→访问→登录→完成抽奖→领取→购物/结算→订单。分享单独关联有效访问、赠次账本和邀请来源订单。客户端记录点击与展示，服务端记录抽奖/发券/奖励/订单成功；复制不是分享完成，零元订单不是付费复购。

验收包括：375宽无横向溢出，812高弹窗无遮挡，三行省略、价格语义、圆点切换、EN/AR RTL、关闭不丢记录、重复点击/超时不重复扣次、全部售罄仍保留展示。纯静态原型只能验证前端呈现，业务并发和真实履约必须另做服务端验收。

## 10. 里程碑与待决策

阶段一：原型评审；阶段二：确定券政策、奖品、成本与公开规则；阶段三：接口、鉴权及真实结算；阶段四：安全、异常与数据验收；阶段五：受控试运行与复盘。无既定上线日期或真实增长结果。

待确认：目标市场/币种、每日时区、券门槛、优惠叠加、实物资格概率、礼品预占/领取/下单期限、取消释放、设备去重、误伤处理、活动预算、数据窗口及发布负责人。
