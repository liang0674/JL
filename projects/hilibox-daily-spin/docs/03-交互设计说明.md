# 美妆电商每日幸运转盘｜交互设计说明

版本：V1.0 · 2026-10-23 · 独立产品案例

案例声明：本项目用于美妆电商产品设计与前端演示。品牌背景、经营规模、业务问题、预算及目标均为模拟，不对应任何真实商家，不构成已验证的商业效果。页面、商品、价格、库存和中奖结果均用于演示。

## 1. 页面与流程目录

活动主页面、商品及记录下屏、规则、普通券结果、实物结果、分享落地页、兑换/下载引导、售罄和活动关闭状态。真实登录、地址结算、支付和商品详情属于电商宿主系统能力，不在独立静态原型中假造实现。

## 2. 视窗与排版

活动内容375×812px，输出@3x JPG为1125×2436px；长页面按首屏和下屏展示，不压缩成长图塞进一个画板。演示手机壳纯色，外框不计入设计稿尺寸。

整体粉色视觉，主色#F7C1D5，按钮深色文字。主按钮、分享引导与奖品模块左右对齐；Free Gift和GRAND PRIZE紧凑同排。商品图片104×100px、contain；标题12px/600，最多3行，超出省略。原价划线，中奖后0价清晰标注。

## 3. 滚动与轮播

正文只在手机内容区纵向滚动；原生滚动条无占位；浮动细条3px、无轨道背景，滚动时出现，650ms后淡出。不得因为出现滚动条导致内容变窄或横向跳动。

轮播3500ms切换，圆点可手动选商品，无数字计数。单件隐藏圆点，页面隐藏时暂停自动切换。商品库存更新后保留仍可用的当前项；已售罄项退出轮播。展示不授予奖品，不绑定抽奖结果。

## 4. 抽奖按钮与状态机

进入→加载配置/次数→可参与。正式环境未登录点击→调用宿主登录→返回重新读取；演示以模拟登录代替。

可抽奖时点击→请求中禁用→收到结果→转盘动画→主动打开结果弹窗→更新记录和次数。动效按奖项ID定位，扇区面积不是概率承诺。重复点击不重复扣次。

剩余机会为0则禁用普通抽奖，提供分享引导。结果领奖按钮根据还有无下一次选择“领取并再次参与”或“领取”；不引导不存在的下一次。

## 5. 普通券弹窗

展示实际中奖优惠、领取状态和有效期。点领取→请求中→成功显示实际券信息；关闭不删除奖励，记录可恢复。继续购物在正式系统进入适用商品列表，原型仅作演示导航。

确定失败显示明确错误并保留原奖品；未知超时显示待确认，通过原requestId查询恢复，禁止新发券请求。重试不延长原有效期。

## 6. 实物弹窗与兑换

展示服务端实际商品快照，图片完整，名称明确。点领取→准备指定SKU免费权益和包邮→正式系统结算→用户提交订单。不得从当前轮播商品推断实际中奖商品。

分享网页领取打开兑换/客户端引导，不在网页直接生成真实券。已领取未下单可继续，已使用或失效不可再兑换；具体恢复需正式服务状态映射。示意商品及原型结果不代表商业承诺。

## 7. 分享与弹层

点分享→正式服务签发链接→渠道面板→复制或外部分享。复制、外部跳转不直接赠次；有效好友打开才记奖励。静态演示只有当前浏览器模拟，不模拟真实安装识别。

弹层阻止底层误触；打开后焦点进入，关闭后回到触发点；Tab范围限制在当前弹层内，Escape按层级关闭。关闭按钮有语义名称，不能靠颜色单独表达成功失败。

## 8. 异常与恢复

| 状态 | 反馈 | 恢复 |
| --- | --- | --- |
| 加载 | 提示等待、按钮禁用 | 配置与记录完成后启用 |
| 次数耗尽 | 剩余0、分享引导 | 后端确认新增机会后刷新 |
| 写入超时 | 待确认 | 查询原请求，不新建重复抽奖 |
| 明确失败 | 本地化原因 | 安全重试，原奖品不丢失 |
| 部分售罄 | 下线对应可用商品 | 其他商品继续轮播 |
| 全部售罄 | Sold out/已抽完 | 保留实物位置，补货后恢复 |
| 活动关闭/结束 | 状态提示 | 保留合法历史权益处理 |
| 会话失效 | 登录引导 | 返回重新查询账号数据 |
| 缺图缺价 | 中性占位/隐藏原价 | 不伪造商品或价格 |

## 9. 多语言与设计边界

英文及阿语RTL为展示案例，中文供辅助演示。阿语布局采用逻辑首尾方向，品牌图、商品图和商品包装文字不整体镜像。价格、长标题、弹窗按钮必须在小屏可读；IQD是界面示例币种，商业测算若用人民币须单独注明。

文档采用中性电商案例，不关联真实品牌、仓库、客户或商店地址。已有历史UI导出中的标识属于旧原型素材，本次未将其纳入独立案例文档包；后续对外展示UI时应另行统一中性品牌和兑换跳转。

## 10. 验收与分析

核对375×812排版及三倍图尺寸、无横向溢出、完整商品图片、三行省略、无占位滚动条、弹层遮罩、关闭保留记录、自动弹出结果、剩余机会文案、EN/AR排版、禁用连点、未知结果恢复。

埋点区分入口曝光/点击、页面、抽奖点击/结果展示、领取、分享渠道、引导及异常；业务完成由服务端事实确认。若要评估具体奖品吸引力，需要另定义轮播可见曝光、商品ID及去重，不把中奖弹窗当商品轮播曝光。
