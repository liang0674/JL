HiliBox 每日转盘｜PRD 产品需求文档

版本：V1.0 · 2026-10-23 · 实现基线：main / f7d1e42 · 内部产品资料

1. 产品目标与当前状态

通过每天可参与的优惠转盘带动用户回访，分享获得更多机会，使用优惠券促进再次购物，Free Gift实物大奖增强吸引力。与新人券、砍价活动并存；转盘承担日常回访和老客复购场景，不自动改变其他活动规则。

前端页面、交互、奖品展示、既有登录/下单跳转与客户端埋点已完成。后端真实账本、资格/概率、库存、发券、分享风控、正式采集和双端联调尚待完成；当前生产配置默认关闭，尚未部署上线。

3. App内用户流程

Shop入口 → 活动页 → 未登录则进入既有登录/注册 → 回到活动页读取账号次数及记录 → 点击免费抽奖 → 服务端确定结果 → 转盘动画 → 主动弹出中奖结果 → 领取权益/继续游戏或购物。

普通券：领取成功后展示券与实际有效期，继续购物进入Hot列表。继续抽奖的按钮文案根据剩余机会判断；没有下一次时使用“领取”，不引导不存在的下一次。

Free Gift：结果弹窗展示实际中奖商品，点击领取获得指定SKU免费券及包邮权益并进入既有结算；用户选择/填写现有地址、确认后提交。中奖或领券时不会立即出现在订单列表；订单提交成功后才显示。

领奖后中途退出应可从记录恢复未完成结算；已下单、已过期的权益不能再次兑换。实际订单状态映射仍需前后端联调补齐。

4. 分享出去的网页流程

好友打开正式分享链接 → 顶部仅HiliBox Logo → 浏览转盘及奖品 → 点击抽奖进入既有注册/登录 → 同账号读取共用次数 → 抽奖并保存中奖记录 → 点击领取展示下载/打开App引导 → App登录同一账号继续领取。

不存在免登录抽奖后再手动绑定中奖数据的流程。网页登录抽过的基础次数会计入同账号App额度；更换入口或安装App不会重新发2次。网页领取本身不发券、不调用claim、不标记已领取。

用户从网页跳应用商店下载或自行下载安装，只要使用同一账号，都应读取同一账本。App唤起及跨端回跳需正式域名和双端真机验收，不能以本地演示证明已完成。

5. 分享奖励流程

用户登录后点右上角或页面分享按钮 → 后端签发链接 → 用户复制或发起WhatsApp分享 → 有效新设备打开链接 → 后端完成活动、去重及风控判断 → 奖励入分享者当日账本 → 分享者返回活动页刷新次数后可用。

点击分享、复制成功或跳外部应用都不直接发次数。重复设备、自邀、无效链接和已关闭活动不发新增奖励。每日分享次数不限，不代表每次打开都有效。设备识别由服务端风控实现；需要明确误伤与申诉口径。

7. 奖池与库存

运营配置3—8个唯一奖项，普通券对应真实券模板。Free Gift只占一个格，内部可绑定多个真实商品/SKU。各商品有真实名称、图片、IQD原价、分配库存与可用库存状态。

单件售罄后退出可用轮播；全部实物售罄时保留实物格并显示“已抽完”，模块显示Sold out并隐藏中奖后0价；普通券继续抽。补货后恢复。已中奖预占的用户仍可按有效期领取，不因其他用户看到售罄撤销权益。

后端独立确定中奖商品并预占库存，再返回商品快照供弹窗、记录和下单使用。当前正式前端不支持直接删除仍被旧记录引用的奖项ID，活动中改奖项结构需版本兼容方案。

8. 状态与异常设计

场景预期结果
无配置/接口异常不开放新抽奖，保持入口隐藏或明确不可用；不回退演示结果
活动未开始/结束/关闭显示对应状态；禁止新抽奖，已有权益按有效期处理
剩余次数为0禁用普通抽奖，引导有效分享赚机会，不展示积分兑换

9. 运营开关与生命周期

enabled控制是否允许参与，entry_visible控制Shop入口是否展示。活动开启但入口隐藏时，已有链接仍可参与；关闭活动时禁止新抽奖与分享赠次。仅隐藏入口不能替代服务端关停。

生命周期：准备正式奖项与规则 → 测试环境联调 → 双端/EN/AR及异常验收 → 明确预算/监控/回滚 → 授权上线 → 日常巡检 → 到期关闭 → 继续处理未过期奖品与订单 → 成本与复购复盘。

本期未单独新增商品轮播曝光/商品切换埋点；若要分析具体奖品吸引力，应另行定义展示可见阈值、商品ID/曝光去重和点击行为后实施，不把现有抽奖结果事件当轮播曝光。

13. 独立展示版本补充

纯静态HTML/CSS/JS，无后端依赖，可GitHub Pages部署。默认模拟已登录；本机存储或受限时内存保存。不得将模拟注册、库存、分享和领奖当真实业务。商品为唇膏、精华、面霜3个原创SVG案例，名称/价格均为示例。

演示外框内容尺寸375×812px，10px纯色手机边框；外框395×832px。原生滚动条隐藏，不占内容宽度；自绘3px悬浮条滚动时出现，停止650ms后淡出，淡出动画250ms。商品标题12px/600字重，最多3行省略；商品图104×100px完整展示；轮播3500ms切换、圆点导航、无数字计数。主粉色#F7C1D5，深色文字；阿语RTL，图片不镜像。

14. 需求优先级与验收

P0：账号统一额度、真实抽奖/领奖幂等、库存预占、免费包邮结算、活动关停与合法历史权益；P1：分享获次、EN/AR、真实采集与商品轮播；P2：轮播单品分析与进一步任务体系，当前未交付。

前端效果验收参考UI-JPG目录；真实业务验收必须在后端联调环境进行。用户目标、预算、归因窗口、礼品期限和券门槛没有确认前，不能以演示数值直接上线。
