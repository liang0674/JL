# 上海迪士尼 App｜扫码点餐用户体验地图

地图类型：基于设计资料重建的任务旅程。用户疑问、情绪与痛点为情境推演，尚未经过用户研究验证；不代表当年真实满意度或转化数据。

## 1. 核心情境

游客在园区游玩期间产生用餐需求，希望通过 App 或现场二维码进入合适的餐厅，完成个人或同行成员的餐品选择，并清楚知道下一步如何继续。

家庭同行是主要分析情境，用于检查套餐、成人 / 儿童分组和多人选餐的复杂性；不据此宣称它是已验证的最大用户群。

## 3. 三个关键体验节点

入口进入服务：关注用户是否到达正确门店，而不只关注扫码是否成功。通用码与门店码承担不同任务，需要保留不同路由。

套餐完成选择：成人、儿童、数量和饮品规格叠加时，用户需要持续知道「已选什么、还差什么」，避免提交时才发现无法完成。

从支付入口到下一步：资料已经展示支付与订单入口，但缺少完整闭环材料。这一阶段应补齐业务依据后继续完善，不能用推演替代上线事实。

## 4. 改进优先级

优先级一：入口识别正确、门店营业分支、登录后回到原目标、必选项校验和订单结果可查询。

优先级二：套餐分组进度、购物车配置回显、金额一致性、中英文信息完整性。

优先级三：分类浏览效率、餐品信息表达、复杂套餐的渐进展开方式。

优先级是复盘建议，需结合真实业务量、问题数据和实现成本再确认。

## 5. 如何验证这张地图

建议用任务测试检查：扫描通用码选店、扫描门店码进入菜单、停业后重新选店、完成含成人与儿童饮品的套餐、修改规格后核对购物车、查找订单入口。

记录任务是否完成、误操作位置、用户的原话、需要求助的环节和恢复路径。情绪变化应通过访谈或测试记录补证，不能直接将本地图中的假设作为结论。

## 6. 设计负责人价值表达

围绕多入口、多码型与不同餐饮服务模式梳理路径，把套餐选择转化为清楚的操作规则，再将这些规则落实到中英双语页面与原生 / HTML 协同说明中，支持跨团队对齐和设计交付。
